1. 研究目的与数据来源

LiCSAR 提供 Sentinel-1 InSAR 处理成果；LiCSBAS2 是利用 LiCSAR 解缠干涉图与相干性产品进行时间序列分析的开源工具。本笔记聚焦于数据处理的前两步：① 构建可复现的软件环境；② 以 114A_05790_131313 为例获取可用于后续时间序列反演的输入数据。

数据产品入口是 COMET-LiCS portal，代码仓库为 yumorishita/LiCSBAS2。请先在门户确认目标 Frame 以及有效观测日期，Frame 编号在这里作为命令示例，并不代表已经验证其当前服务状态。

2. 环境配置与安装

2.1 克隆官方代码

Bash · source
git clone https://github.com/yumorishita/LiCSBAS2.git
cd LiCSBAS2

2.2 创建独立 Conda 环境

官方推荐使用仓库自带的 LiCSBAS.yml 创建环境。当前官方说明要求 Python 3.12 或更新版本；使用 YAML 构建环境优于将依赖手工安装进已有环境。

Bash · environment
conda env create -f LiCSBAS.yml
conda activate licsbas2
python --version

2.3 配置命令环境并验证

Bash · verify
source bashrc_LiCSBAS.sh
LiCSBAS_check_install.py
终端提示：source 只对当前 shell 会话生效。若新开终端后找不到 LiCSBAS01_get_geotiff.py，需重新激活 Conda 环境并加载对应 shell 配置。这里采用官方提供的 bashrc_LiCSBAS.sh。

3. 建立独立工作目录

安装完成后，从 LiCSBAS2 源代码目录返回上级目录，按 Frame ID 建立独立工作区，避免将下载数据直接写入软件代码目录。

Bash · workspace
cd ..
mkdir -p 114A_05790_131313
cd 114A_05790_131313
pwd

此时当前工作目录应以 114A_05790_131313 结尾。后续 Step 01 在当前工作目录创建数据子目录。

4. 下载指定 LiCSAR Frame

运行 Step 01，下载可用的解缠干涉图（unwrapped interferograms）、相干性（coherence）以及相关辅助数据。命令中的 -f 指定 Frame ID；不指定日期时将尝试检索该 Frame 的可用数据。

Bash · full availability
LiCSBAS01_get_geotiff.py -f 114A_05790_131313

该命令与早期 LiCSBAS 下载工具同名，但本文使用 LiCSBAS2 的环境与脚本，不要误以为两个仓库的安装和依赖要求完全一致。

5. 按研究时段筛选干涉图

为降低数据量、对齐研究时段，可以加 -s 与 -e，日期格式均为 YYYYMMDD。

5.1 示例 A：2015–2016 年

Bash · short window
LiCSBAS01_get_geotiff.py \
  -f 114A_05790_131313 \
  -s 20150101 \
  -e 20161231

5.2 示例 B：2015–2025 年

Bash · extended window
LiCSBAS01_get_geotiff.py \
  -f 114A_05790_131313 \
  -s 20150101 \
  -e 20251231
日期核对：原始草稿一处写“2015–2025”，但参数 -e 20161231 实际表示截止 2016-12-31。本笔记分别提供两种示例，避免误下载。日期条件限制的是所检索干涉图的时间范围，实际返回量还取决于该 Frame 的公开产品覆盖情况。

6. 输出目录与数据说明

正常运行后，预期会在工作区生成 GEOC/ 目录。以下为示意结构（某些文件的实际命名和可用性可能因 Frame 和软件版本而变化）：

Directory tree · schematic
114A_05790_131313/
└── GEOC/
    ├── 114A_05790_131313.geo.E.tif
    ├── 114A_05790_131313.geo.N.tif
    ├── 114A_05790_131313.geo.U.tif
    ├── 114A_05790_131313.geo.hgt.tif
    ├── baselines
    ├── metadata.txt
    ├── YYYYMMDD_YYYYMMDD/
    │   ├── YYYYMMDD_YYYYMMDD.geo.unw.tif
    │   └── YYYYMMDD_YYYYMMDD.geo.cc.tif
    └── YYYYMMDD_YYYYMMDD/
        ├── YYYYMMDD_YYYYMMDD.geo.unw.tif
        └── YYYYMMDD_YYYYMMDD.geo.cc.tif
产品物理/技术含义后续用途
*.geo.unw.tif已解缠的干涉相位 GeoTIFF；相位不是直接的垂直位移。相位差、形变时间序列反演
*.geo.cc.tif干涉相干性（coherence）栅格。质量评价与低相干区筛选
*.geo.E/N/U.tif与雷达视线方向相关的东、北、上几何分量。LOS 几何解释及分量转换
*.geo.hgt.tif高程/地形栅格（DEM 相关数据）。地形信息及空间参照
baselines基线信息。干涉网分析和诊断
metadata.txtFrame 元数据。记录产品与几何属性
科学解释：单轨 LOS 观测一般无法独立反演完整三维位移，且解缠相位可能包含大气延迟、轨道误差、地形残差等非形变信号。时间序列结果应当结合参考点、质量控制与误差评估使用。

7. 数据检查与常见问题

完成下载后建议保留终端日志，并至少检查目录、数据数量和时间覆盖。以下 shell 命令可直接执行，不修改已下载文件：

Bash · audit
pwd
ls -lh GEOC | head
find GEOC -name '*.geo.unw.tif' | wc -l
find GEOC -name '*.geo.cc.tif' | wc -l
find GEOC -maxdepth 1 -type f | sort

如果统计为零，应先核对 Frame ID、LiCSAR 数据服务可用性、日期过滤范围及下载日志，而不是直接进入 SBAS 反演。检查脚本也应确认在当前 shell 中可以被识别：

Bash · environment diagnostics
command -v LiCSBAS01_get_geotiff.py
conda info --envs
python --version

若遇到远程下载失败，需要考虑 LiCSAR 服务端地址变动。COMET-LiCS Portal 官方已提示使用更新的代码；处理问题时应核对实际安装的脚本版本，而非直接假定网络错误等于 Frame 不存在。

8. 局限性与下一步

  • 本笔记仅覆盖安装与 Step 01 数据获取；尚未执行多视处理、干涉图质量筛选、闭环检验或 SBAS 时间序列反演。
  • 数据可用性、下载成功率和空间覆盖与 LiCSAR 门户当前发布状态相关，本文不宣称已有该 Frame 的实际下载结果。
  • 建议后续笔记继续介绍 LiCSBAS02 多视预处理、Step 11–12 质量控制和 Step 13 时间序列反演，并记录工作区域、参考点、时段与处理版本。
